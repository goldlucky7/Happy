# 여행 스탬프북 제작 스킬

부부(사용자 + 신랑) 2인용 여행 팸플릿 웹사이트를 만드는 스킬. 제주 스탬프북(https://goldlucky7.github.io/jeju/)과 동일한 구조로 새 지역 버전을 만든다.

## 사용자 성향 (반드시 준수)

- **비개발자, 안드로이드 폰으로만 작업.** 기술 용어 최소화, 결과 위주로 소통
- **번거로운 것 싫어함.** 질문은 꼭 필요한 것만 1~2개로 압축 (지역, 장소 개수 정도)
- 신랑은 Claude 계정 없음 → 반드시 GitHub Pages 링크로 배포 (Claude 게시 링크 금지)
- 로그인·코드입력 없는 자동 연동 필수 (TextDB 10초 폴링 방식 유지)
- **팩트체크 중시**: 모든 장소의 주소·영업시간을 지도/웹검색으로 교차 검증. 미확인 정보는 "매장 확인"으로 표기 (지어내기 절대 금지)

## 완성품 스펙 (제주판 = 318곳 기준)

### 첫 화면 구성 (2026-08 전면 정리 · 이 순서를 지킬 것)
처음 보는 사람이 헤매지 않도록 **위에서 아래로 한 갈래**가 되게 짰다.

```
머리말(제목 + 두 줄 설명 + 진행률)      ← 긴 설명을 여기 두지 말 것
장소 종류 탭 (한 줄 가로 스크롤·sticky)
🔍 검색 + 세부 칩 + 지금 필터 바
─ 내 여행 ─   ⭐꼭 가볼 곳 · 🗓내 일정 · 🔴갔다온 곳      (타일 3)
─ 여행 도구 ─ 📍내 주변 · 🆕요즘 뜨는 곳 · ✈️항공편
              🎟할인 쿠폰 · 🕐영업시간표 · ➕장소 추가     (타일 6)
─ 골라 보기 ─ 🧭얼마나 움직여야 하나요? ▾ · 📍지역별로 보기 ▾  (접이식)
❓ 처음이신가요? ▾   ← 긴 사용법 설명은 전부 여기로
목록
```

**지킬 것**
- 구역마다 **작은 제목**(`.sec-lab`)을 달아 무엇을 하는 곳인지 알린다
- 내 여행·여행 도구는 **아이콘+이름 타일**로 모양을 통일한다(`.tool` / `#myRow .tab`).
  ⚠️ **큰 그라데이션 버튼을 여러 개 만들지 말 것** — 전부 똑같이 소리쳐서 뭐가 중요한지 안 보인다
- ⚠️ **떠다니는 버튼(`position:fixed`)을 만들지 말 것.** 본문을 가려서 "정신없다"의 주범이었다
  (장소 추가·영업시간표는 이제 도구 타일이다)
- 넓은 화면에서 타일이 늘어지지 않게 `repeat(auto-fill,minmax(112px,1fr))`을 쓴다
- 머리말 제목은 **형광 주황**(`#FF7A1A` + 빛번짐)이다. 바다색 배경 위에서 눈에 들어오게 한 것

### 카테고리·탭
- 9개 카테고리: 관광지 99 + 맛집 55 + 카페 49 + 소품샵 12 + 술집·안주 15 + 호텔 15 + 마사지 26 + 가성비 카페 24 + 탈것·놀이기구 23 (카페 49곳 안에 🍧 빙수·팥빙수 8곳 포함)
- **장소 종류 탭은 한 줄 가로 스크롤**(`#tabs`): 전체 / 🏝 관광지 / 🍽 맛집 / ☕ 카페 / 💸 가성비 카페 / 🛍 소품샵 / 🍻 술집·안주 / 🏨 호텔 / 💆 마사지 / 🎢 탈것·놀이기구
- **내 기록은 따로 뗀다**(`#myRow` 타일 3개): ⭐ 꼭 가볼 곳(0/32) / 🗓 내 일정 / 🔴 갔다온 곳
  - ⚠️ 장소 종류와 내 기록을 **한 덩어리로 섞지 말 것.** 예전에 12개를 한곳에 두니 여러 줄로 흩어져 "정신없다"는 말을 들었다
  - 두 곳 모두 `.tab[data-filter]`이므로 **클릭은 `document`에서 받는다**(한쪽 컨테이너에 걸면 다른 쪽이 죽는다)
- ⚠️ 헤더의 곳수 표기(`... · N PLACES`)는 실제 PLACES 개수와 **반드시 맞출 것**. 첫 화면을 정리하면서 소개 문장이 하나 늘어 이제 **`<title>` · 헤더 `· N PLACES` · 머리말 소개문 · 「처음이신가요?」 안내문 네 군데**이고, 따로 놀기 아주 쉬우니 넷을 한꺼번에 고치고 `grep`으로 옛 숫자가 남았는지 확인할 것 (제주판은 263 → 295 → 318로 맞춰왔다)
- **도장 찍은 곳은 목록에서 사라지고 [🔴 갔다온 곳] 탭에 모임** (`passes()`에서 처리)

### 우선 추천 (카테고리별 "꼭 가야 할 곳")
- ⭐ **꼭 가볼 곳 탭(MUST)**: 필수 코스 모음. 이 탭은 **거리·지역·강도 필터를 자동 해제**하고 섬 전체를 보여줌. 카드에 "왜 꼭 가야 하냐면" 한 줄 이유
- 🔥 **MUSTEAT**(죽어도 맛봐야 할 집) — "이건 제주에서만" 이유 문구
- 소품샵/술집/호텔은 **티어 그룹**으로 묶어 출력 (TIERMAP)
  - 소품샵: 💎 죽어도 가봐야 하는 / 🎀 특이한 / 🛍 그 밖의
  - 술집: 🔥 죽어도 가야 할 / 🍺 맥주 한잔 / 🍢 대표 안주가 확실한
  - 호텔: ✨ 청소·친절 우수 / 🏨 그 밖의 3~5성급 + 성급 배지(STARS)
  - 마사지: 🌿 오일·아로마 테라피 / 👐 중국식·발마사지·지압 / 🇹🇭 타이마사지 (SPA_T·MUSTSPA)
- 💸 **가성비 카페**는 티어 대신 **상황별 3그룹**(CHEAP_GROUPS): 🌊 바다·경치 좋은 지점 / 🚗 이동 중 들르기 좋은 지점 / 🏙 시내·시장 안. 빽다방·메가커피·컴포즈 중 **자리나 위치가 쓸모 있는 지점만** 선별
- 🎢 **탈것·놀이기구**도 티어 대신 **무엇을 타느냐로 5그룹**(RIDE_GROUPS): 🚢 배 타고 나가기(잠수함·유람선·요트·도항선) / 🏎 직접 몰아보는 것(카트·ATV·버기·레일바이크) / 🪂 하늘로 뜨는 것(짚라인·패러글라이딩) / 🎢 놀이기구·테마파크 / 🐴 말 타기
  - 탭 맨 위 안내문에 **거의 다 예약제이고 기상에 따라 결항한다**는 주의와, **이미 관광지 탭에 들어 있는 탈것**(제주=9.81파크·에코랜드 기차·쇠소깍 카약·섬 배편)을 어디서 찾는지 함께 적는다. 같은 장소를 두 카테고리에 중복으로 넣지 말 것

### 필터·탐색
- 🔍 검색창: 이름·지역·태그·해시·설명·주소 통합, 띄어쓰기 무시, **초성 검색**(예: ㅇㅈㅎㅈㄱ), ✕ 초기화
- 세부 카테고리 칩 16개: **카테고리 + 맛집 종류 + 키워드 3중 판정**(`chipMatch`)
  - 칩은 탭 하나에 묶이지 않아도 됨. `cats`에 카테고리를 여러 개 넣으면 **탭을 가로지르는 테마 칩**이 된다 (예: `🍧 빙수·팥빙수` = `cats:["cafe","food"]`로 카페·맛집을 한꺼번에 잡음)
- 📍 지역별로 보기: 권역 버튼 10개 (이모지·이름·곳수, 재클릭 해제) + 카드에 권역 배지
- 🗂 **「얼마나 움직여야 하나요?」와 「지역별로 보기」는 접이식**(`setupFold`). 평소엔 접혀 있고 눌러야 열린다.
  목록이 길어 첫 화면을 다 먹기 때문이다. **접혀 있어도 지금 무엇이 골라져 있는지 머리글에 적어준다**
  (예: `📍 지역별로 보기 · 애월`). 안 그러면 접힌 채로는 뭐가 걸려 있는지 알 수 없다
- 📍 **내 주변 15km 이내 보기**(NEAR_LIMIT_KM): 위치 권한 → 직선거리 가까운 순 상위 30곳, 🧭 거리 배지
- 🧭 **얼마나 움직여야 하나요?(EFF)**: 실내 → 시원한 야외 → 차로 바로 → 야외 → 걷는 곳 → 약간 등산. **덜 힘든 순서로 그룹핑**, 카드에 강도 배지. 더운 날·비 오는 날 대응
- 맛집은 종류별 그룹(FT 8종): 해산물·회 / 해장국·국밥 / 국수 / 흑돼지·고기 / 돈까스 / 수제버거 / 김밥·분식·치킨 / 그 외
- **지금 필터 바**: 켜져 있는 필터를 태그로 보여주고 개별 ✕ 해제 + 현재 곳수 + [전체 해제]
- 위 필터는 전부 동시 적용(AND)

### 카드 정보
- 🅿️ **주차 정보(PK)**: 무료 / 무료·좁음 / 유료 / 인근 공영 / 갓길 배지 + 안내 팁 + [이 근처 주차장 지도로 보기]
- 📋 **주소 복사** 버튼, 📷 **대표 사진 보기**(네이버 이미지 검색), 📞 **전화 걸기**(TEL, 탭하면 바로 통화)
- 카드마다 **바깥 링크 3종**: 🗺 네이버지도(`NM`) · 관광포털 검색(`VJ`) 또는 관련 기사 · 📝 **후기·정보**(`REV` = 네이버에서 "장소명 지역 후기" 검색)
  - ⚠️ 링크 헬퍼는 **반드시 장소 이름을 받아 검색 주소를 만드는 함수**여야 함. 홈페이지 주소만 넣으면 어느 카드를 눌러도 메인으로 가버림
- 맛집·카페·술집: 영업시간/브레이크타임/휴무일 3줄 + 🕐 영업시간표 전체 모달
- 술집은 🍢 대표 안주(anju) 줄 추가

### 도우미 기능
- 🤖 **모르는 말 바로 찾기(GLOSSARY ~78개)**: 카드 설명에서 사전에 있는 말에 **점선 밑줄**이 자동으로 그어지고, 누르면 뜻 팝업. 검색창으로도 찾기 가능
  - 사전에 없는 말은 **아무 글자나 길게 눌러 선택 → [🤖 이 말 뜻 찾기]** 버튼 → AI(Perplexity)·검색·사진 링크로 연결
- 🆕 **요즘 뜨는 곳 업데이트 받기**: 같은 폴더의 `updates.json`을 읽어 새로 뜨는 장소를 카드로 보여주고, 개별 담기 / [전부 내 목록에 담기] 가능. 이미 목록에 있는 곳은 "이미 담김" 처리
- ⭐ **내 일정 탭(plan)**: 카드마다 [☆ 가보고 싶어요]를 누르면 여기에 모임. 곳마다 **방문 예정 날짜** 지정 가능하고, **📍 지역별 / 📅 날짜별** 묶음 보기를 버튼으로 전환. 날짜 정한 곳·다녀온 곳 수를 위에 요약
- 🚗 **동선 순서**: 내 일정의 각 묶음(지역·날짜) 안을 **들르기 좋은 순서로 자동 정렬**. 카드에 순번(①②③)과 **앞 지점에서의 거리**가 붙고, 묶음 머리글에 `🚗 동선 순서 · 총 ○○km` 표시
  - 출발 방향은 **내 위치를 알면 가까운 쪽에서**, 모르면 **공항에서 가까운 쪽에서** 시작
  - 좌표 없는 곳은 순번 없이 맨 뒤로 밀리고 "순서를 못 매긴 곳 N곳"으로 안내
- 🎟 **그 지역에서 쓸 수 있는 할인(`COUPONS`)**: 폰으로 받아 **보여주기만 하면 깎아주는** 제도를 카드로 안내.
  제주판은 4가지 — 🪪 나우다(제주 공식 디지털 관광증, 가맹점 10%·공영관광지 27곳 무료/50%) ·
  💳 탐나는전(제주 지역화폐, 10% 캐시백·착한가격업소 15%) · 🗓 문화가 있는 날(매월 마지막 수요일) ·
  🌅 성산일출봉 무료 관람의 날(매월 첫째 주 월요일)
  - ⚠️ **새 지역판은 그 지역 것을 반드시 새로 조사할 것.** 지역화폐·디지털 관광증은 지자체마다 다르다
    (부산=동백전, 전주=전주사랑상품권 등). 제주 것을 그대로 두면 완전히 틀린 정보가 된다
  - ⚠️ **출처를 확인한 것만 넣는다(지어내기 절대 금지).** 혜택·기간·비율은 자주 바뀌므로
    화면에 **"○○년 ○월 조사 시점 기준"**과 항목마다 **[바로가기] 링크**를 반드시 함께 적을 것
- ✈️ **항공편 · 탑승권 읽기**: [✈️ 항공사 운영시간 · 탑승권 읽기] 버튼 하나에 세 화면이 들어 있음
  - 🎫 **탑승권 읽기** — **[📸 탑승권 찍어서 읽기]**(폰 사진 앱을 열어 찍는다) / [🖼 저장된 사진에서 찾기] / [⌨️ 직접 입력].
    탑승권 바코드에서 편명·출발/도착 공항·날짜·좌석·예약번호·이름을 읽음
    - ⚠️ **탑승권 바코드에는 출발 시각과 탑승구가 없다**(국제 규격 자체에 그 칸이 없음). 출발 시각만 한 번 넣으면 **공항 도착 권장 / 수속·수하물 마감 / 탑승 시작 / 탑승구 마감 / 남은 시간**을 계산해줌
    - 저장하면 메인 화면 위쪽에 **다음 항공편 카운트다운 바**가 뜨고, 누르면 바로 그 화면으로 감
    - 🔒 탑승객 이름·예약번호가 들어가므로 **두 사람 공유 저장소에 올리지 않고 각자 기기에만 저장**(`jeju_flights_v1`). 이 원칙을 깨고 공유 저장소로 옮기지 말 것
    - 📄 **번들거리는 종이 탑승권도 읽는다.** 자리마다 밝기를 따로 재는 방식(`adaptiveBin`)과 선명화(`unsharp`)를 섞어 쓰기 때문
    - 🤖 **인식기 한 개가 죽어도 안 멈춘다.** 매 프레임 기기 내장 → ZXing/jsQR 순으로 **둘 다** 돌린다. 내장 인식기가 유일한 길이 되는 구조를 만들지 말 것
  - 🕐 **항공사 운영시간** — 그 지역 노선 항공사의 고객센터 번호·상담시간·수속 마감 기준을 카드로. 공항 콜센터도 함께
  - 🧭 **공항에서 어디로** — 공항 층별 구조와 탑승까지 단계 안내. 탑승구는 당일 배정이라 **실시간 운항정보 링크**로 연결
- ➕ 장소 추가/삭제(카테고리·강도·메모 선택), 백업/복원, 두 사람 도장·추가 장소·가보고 싶은 곳·할인율 자동 연동(로그인 없음)
  - 저장 구조: `{v:도장, c:추가한 장소, w:가보고 싶은 곳+날짜, r:예비 칸}`
    - `r`은 지금 화면에서 쓰지 않지만 **병합에서 절대 빼지 말 것.** 빠뜨리면 상대방 기기의 기록이 날아간다

## 제작 순서

### 1단계. 요구 확인 (질문 최소화)
지역이 명확하면 개수·컨셉만 짧게 확인하고 바로 시작. 기본값: 관광지 60 + 맛집 30 + 카페 25 + 소품샵 10 + 술집 12 + 호텔 12 + 마사지 15 + 가성비 카페 15 + 탈것 15 (지역 규모에 맞게 조정).

### 2단계. 템플릿 다운로드 (처음부터 코딩 금지)
```
GET https://raw.githubusercontent.com/goldlucky7/jeju/main/index.html
GET https://raw.githubusercontent.com/goldlucky7/jeju/main/updates.json
```
bash에서 curl로 받는다. 이 파일이 검증된 완성 코드이므로 **데이터만 교체**하고 로직은 절대 건드리지 않는다.

### 3단계. 장소 조사 + 검증 (가장 중요)
- 웹검색으로 해당 지역 인기 장소 후보 선정 (최신 트렌드 반영, 20~40대 취향)
- 지도 검색 도구(places_search)로 **전 장소 검증** (10개씩 묶어 조회). 장소마다 아래를 함께 수집:
  - 주소 · 영업시간/브레이크타임/휴무일 (미확인은 "매장 확인")
  - **위도·경도** (내 주변 기능용 LL) — 못 구한 곳은 **지어내지 말고 LL에서 빼둘 것.** 좌표가 없으면 그 장소만 [내 주변]·동선 순번에서 빠질 뿐 나머지는 정상 동작한다. 대신 **좌표를 못 넣은 곳이 몇 곳인지 사용자에게 반드시 알릴 것** (지도 사이트가 막혀 있는 환경도 있다)
  - **전화번호** (TEL) — 확인된 곳만
  - **주차 상황** (무료/무료좁음/유료/공영/갓길 중 하나)
  - **활동 강도** (실내/시원한 야외/차로 바로/야외/걷는 곳/약간 등산)
  - 맛집이면 **음식 종류** (해산물/해장국/국수/고기/돈까스/버거/분식/그 외)
- 호텔은 성급, 술집은 대표 안주, **마사지샵은 시술 계열**(오일·아로마 / 중국식·발 / 타이)도 함께 조사
- **가성비 카페**는 저가 프랜차이즈(빽다방·메가커피·컴포즈 등) 지점 중 **오션뷰·드라이브 동선·시내 접근성** 같은 이유가 있는 곳만 고르고, 그 이유를 그룹(바다·경치 / 이동 중 / 시내·시장)으로 분류
- **탈것·놀이기구**는 그 지역에서 **실제로 몸을 싣는 것**만 고른다 (구경만 하는 전망대·박물관은 제외). 배·잠수함·유람선·요트 / 카트·ATV·버기·레일바이크 / 짚라인·패러글라이딩 / 놀이공원 / 승마 순으로 훑고, 장소마다 **예약 조건(당일 가능 여부·마감 시각)·기상 결항 여부·나이/신장/체중/면허 제한·휴무일**을 함께 적는다. 이것들이 desc·time의 핵심이라 빠지면 카드가 쓸모없다
  - 이미 다른 카테고리(주로 관광지)에 들어 있는 탈것은 **옮기지도 복제하지도 말고** 그룹 안내문에서 "관광지 탭에 있어요"로 안내만 한다
- **한 테마로 3곳 이상 모이면 칩 후보**다. 그 지역의 대표 간식·디저트를 따로 묶어 조사할 것 (제주=팥빙수, 부산=씨앗호떡·밀면, 전주=콩나물국밥 등). 조사할 때 그 테마가 **카페·맛집 중 어느 탭에 흩어져 있는지**도 같이 적어두면 칩 `cats`를 바로 채울 수 있다
- **렌터카 제휴 할인**: 그 지역 렌터카사의 제휴 쿠폰팩 페이지를 찾아 제휴처 목록·할인율을 수집 (확인 안 되면 할인율은 비워두기)
- **관문(공항·역) 정보**: 항공편 기능에 쓸 자료를 같이 조사한다
  - 그 지역에 취항하는 **항공사 목록 + 고객센터 번호 + 상담 운영시간 + 수속 마감 기준**
  - 공항 **여객터미널 층별 구조**(몇 층이 출발/도착/탑승장인지)와 탑승까지의 단계
  - 공항 **실시간 운항정보 페이지 주소**와 공항 코드(예: 제주=CJU)
  - ⚠️ 카운터 번호·탑승구 번호는 **날마다 바뀌므로 적지 말 것.** "전광판에서 확인"으로 안내하고 실시간 조회 링크를 건다 (틀린 번호를 적으면 공항에서 헤맨다)
  - 내륙 지역이라 공항이 없으면 KTX역 등 **관문 기준으로 바꾸거나 이 기능을 통째로 빼면 된다**
- PLACES 항목 구조: `{id, cat(spot|food|cafe|shop|bar|hotel|spa|cheap), emoji, region, name, tag, hash, desc, addr, time(관광지용) 또는 open/brk/closed(가게용), anju(술집), links:[["네이버지도",NM("이름")],[관련 링크]]}`
- id는 영문 소문자, 기존 항목과 중복 금지
- **장소 이름(name)은 지도에서 실제로 검색되는 형태로** 적을 것 (링크·사진·후기 검색이 전부 이름 기반이라 안 맞으면 엉뚱한 결과가 뜸)
  - 프랜차이즈 지점은 공식 지점명보다 **위치를 붙인 이름**이 잘 잡힘 (예: `빽다방 제주도두점` → `빽다방 (도두 서해안로)`)
  - 시장·상가 안의 가게는 도로명보다 **지번 + "○○시장 내"** 표기가 정확 (예: `서귀포시 서귀동 275-29 (서귀포매일올레시장 내)`)
  - 브랜드명 자체가 맞는지도 확인 (지점 이름만 보고 브랜드를 잘못 적는 실수가 잦음)

### 3-1단계. 팩트체크 — 하노이판에서 실제로 틀렸던 것들

하노이판 193곳을 나중에 전수 재검증했더니 45군데가 틀려 있었다. **다음 다섯 가지가 반복해서 나온다.**

1. **없어진 건물·가게를 그대로 적는다.** 하노이 호안끼엠의 "함까맙(Hàm Cá Mập)" 건물은 2025년 7월에 철거됐는데, 그 안에 있던 유명 카페가 한국 블로그에는 아직 추천으로 남아 있어 그대로 옮겨졌다.
   → **랜드마크·유명 노포는 "철거", "폐업", "이전", "closed"로 한 번 더 검색할 것.** 한국어 블로그는 몇 년씩 갱신이 안 된다
2. **입장료·개방시간이 통째로 틀린다.** 베트남 유적은 2024~2025년에 요금을 크게 올렸다(탕롱 황성 3만→10만동). 묘·능·박물관은 **오전에만 열거나 점심에 닫는 곳**이 많은데 "09:00~17:00" 식으로 뭉뚱그리기 쉽다.
   → **요금은 "인상"·"2025"를 붙여 검색하고, 개방시간은 공식 사이트나 최근 후기로 확인.** 계절제·휴관일·연간 보수 휴관까지 적을 것
3. **널리 퍼진 헛소문을 옮긴다.** "롱비엔 다리는 에펠이 지었다"는 여행기사 절반이 그렇게 쓰지만 사실이 아니다(실제 시공은 데데&필레).
   → **"○○가 지었다/최초다/가장 오래됐다" 같은 문장은 반드시 한 번 더 검증.** 틀린 게 확인되면 카드에 **바로잡는 문장을 넣어주면** 오히려 재미있는 정보가 된다
4. **수상 이력·등급을 부풀린다.** 미쉐린은 **스타 / 빕구르망 / 셀렉티드**가 전혀 다른 등급인데 뭉뚱그려 "미쉐린 맛집"이 되고, 근거 없는 "N년 연속"이 붙는다. 후기 수·평점도 어림수로 부풀려진다.
   → **등급명을 그대로 적고, "연속"·"1위" 같은 말은 근거를 찾은 것만.** 후기 수는 실제 표시값으로
5. **주소가 뭉개져 있거나 행정구역이 틀린다.** "○○ 일대", "구시가지 인근"처럼 적힌 카드는 지도에서 못 찾고, 구(區) 이름을 잘못 적으면 **지역별 보기에서 엉뚱한 동네에 뜬다**(하노이 Giảng Võ는 동다가 아니라 바딘).
   → **번지까지 적을 것.** 그리고 주소를 고쳤으면 **`LL`(좌표)도 반드시 같이 고친다** — 안 그러면 "내 주변" 거리가 어긋난다

**이름 없는 카드를 만들지 말 것.** "루프탑 스카이 바", "재즈 클럽"처럼 상호 없이 뭉뚱그린 카드는 지도 링크가 엉뚱한 데로 가고 사용자가 못 찾아간다.
확인된 실명이 없으면 그 카드는 **넣지 말거나**, 최소한 대표 한 곳을 실명으로 짚어 준다.

**확신이 없으면 어림수를 적지 말고 아예 뺀다.** "소액 입장료", "60년 된 집" 같은 표현을 적어 두면
다음 사람이 그걸 사실로 믿고 그대로 옮긴다. 확인된 숫자가 없으면 종류만 적고 "현장 확인"으로 넘긴다.

### 4단계. 코드 수정 — 교체할 데이터만
아래 목록을 **새 지역 데이터로 전부 교체**한다. 하나라도 빠지면 해당 기능이 조용히 죽으므로 반드시 확인:

| 데이터 | 내용 | 누락 시 증상 |
|---|---|---|
| `PLACES` | 장소 본문 전체 | — |
| `CHIPS` | 세부 카테고리 칩 (cats/ft/keys). `cats`에 카테고리를 여러 개 넣으면 탭을 가로지르는 테마 칩이 됨 | 칩 눌러도 0곳 |
| `ZONES`/`ZONE_OF`/`ZONE_KW` | 권역 목록·id 매핑·주소 키워드 | 권역 배지 없음 |
| `LL` | 장소 좌표 `id:[위도,경도]` | 내 주변 목록에서 빠지고 **동선 순번도 안 매겨짐** |
| `JEJU_AIRPORT` | 동선 출발 기준점 `[위도,경도]` | 동선 방향이 엉뚱하게 잡힘 |
| `EFFORT` | id별 활동 강도 | "미분류"로 빠짐 |
| `PK` | id별 주차 유형 | 주차 배지·팁 없음 |
| `TEL` | id별 전화번호 | 전화 버튼 없음 |
| `FTYPE` | 맛집 id별 음식 종류 | 맛집 종류 그룹 어긋남 |
| `MUST` | 필수 코스 + 이유 문구 | ⭐ 탭이 빔 |
| `MUSTEAT` | 죽어도 맛봐야 할 집 + 이유 | 맛집 강조 사라짐 |
| `MUSTSHOP`/`SHOPTIER`, `MUSTBAR`/`BARTIER`, `MUSTHOTEL`/`HOTELTIER`, `STARS`, `MUSTSPA`/`SPATIER` | 소품샵·술집·호텔·마사지 추천/티어/성급 | 티어 그룹 어긋남 |
| `CHEAPG`/`CHEAP_GROUPS` | 가성비 카페 id별 그룹(바다/이동/시내) | 가성비 탭이 그룹 없이 쏟아짐 |
| `RIDEG`/`RIDE_GROUPS` | 탈것 id별 그룹(배/몰기/하늘/놀이기구/말) | 탈것 탭이 그룹 없이 쏟아짐 |
| `COUPONS` | **그 지역**의 할인 제도(지역화폐·관광증·무료 개방일). 제주 것을 그대로 두면 완전히 틀린 정보가 된다 | 🎟 할인 쿠폰 창이 남의 지역 정보를 보여줌 |
| `GLOSSARY` | 그 지역 용어 사전 | 점선 밑줄 사라짐 |
| `AIRLINES` | 그 지역 노선 항공사 + 고객센터 번호·상담시간·수속 마감(분) | 운영시간 화면이 엉뚱한 항공사로 채워짐 |
| `AIRPORTS` | 공항 코드→한글 이름 + 실시간 운항정보 경로(`kac`) | 편명을 읽어도 공항이 코드로만 나오고 실시간 링크가 죽음 |
| `CJU_LIVE` | 그 지역 공항 실시간 출발·도착 페이지 주소 | [실시간 운항·탑승구] 버튼이 제주로 감 |
| `AP_STEPS` | 공항 층별 구조·탑승까지 단계 안내 | "공항에서 어디로" 화면이 제주공항 설명 그대로 남음 |
| `VJ`(관광포털 검색) / `REV`(후기 검색) | 카드 바깥 링크를 만드는 함수 | 링크가 엉뚱한 곳으로 가거나 후기 버튼이 사라짐 |

- 제목/헤더 문구를 새 지역으로 (예: "부산 여행 스탬프북"). **헤더의 `· N PLACES` 숫자는 실제 PLACES 개수를 세어서 정확히 넣을 것**
- 칩·권역·강도는 **실제 PLACES 데이터에 등장하는 단어**로 구성. 완성 후 버튼마다 곳수 0이 아닌지 확인
- **동선 출발 기준점(`JEJU_AIRPORT`)을 새 지역의 관문으로 교체** (그 지역 공항·KTX역 등 여행 시작점 좌표). 변수명은 그대로 두고 값만 바꿔도 됨
- 검색창 placeholder 초성 예시도 새 지역 대표 장소로 교체
- **`VJ`는 그 지역 관광포털 검색 주소로 교체** (제주=비짓제주). 해당 포털이 없으면 대표 관광 사이트나 관련 기사 링크로 대체. `REV`(네이버 후기 검색)는 지역과 무관하므로 그대로 사용
- GLOSSARY는 그 지역 방언·향토음식·지형 용어로 재구성 (제주판 오름·곶자왈·몸국 등은 제주 전용)
- 테마색은 지역 특색으로 변경 가능 (제주=청록+감귤). 예: 부산=바다남색+갈매기, 전주=한옥 갈색+먹색
- **TextDB 커플 키는 반드시 새로 생성**: `{지역영문}stamp_` + 랜덤 32자리 hex (예: `busanstamp_a1b2...`)
  - ⚠️ 제주 키(`jejustamp_3c5491d5379e4abce2a377bae7987b6c`)를 재사용하면 데이터가 섞이므로 절대 금지
- `updates.json`도 새 지역용으로 같은 폴더에 함께 배포 (아래 스키마 참고)
- **인식기 파일 `lib/` 를 반드시 같이 둘 것**: 탑승권을 읽는 프로그램(`lib/zxing.min.js`, `lib/jsQR.js`)이 저장소에 들어 있고 페이지가 이 경로를 먼저 읽는다.
  - 새 지역도 **같은 jeju 저장소 안에** 만들면 `lib/`를 공유하므로 손댈 것이 없다
  - 다른 저장소로 옮길 땐 `lib/` 폴더를 **통째로 같이 복사**할 것. 빠뜨리면 외부 주소로 받으러 가는데, 막힌 통신망이나 광고 차단기 뒤에서는 인식이 통째로 죽는다
- **로직은 전부 변경 금지**: `toCho` `matchesSearch` `chipMatch` `zoneOf` `effOf` `pkOf` `ftOf` `passes` `render` `makeCard` `distKm` `fmtDist` `glossify` `openUpd` `drawUpd` `copyAddr` `setAiLinks` `renderPlan` `renderPlanByZone` `renderPlanByDate` `toggleWish` `setWishDate` `saveWish` `addCheapGroups` `addRideGroups` `addTierGroups` `setupFold` `foldNow` `drawCoupons` `fmtDay` `daysAway` `routeOrder` `addRouteGrid` `routeNote` `hopKm` `pathLen` `llOf`, fetch→병합→push 패턴, 10초 폴링, visibilitychange
  - 항공편 쪽도 전부 변경 금지: `parseBCBP` `bcbpShift` `parseLoose` `parsePass` `julianToISO` `flightTimes` `pickEngine` `startScan` `stopScan` `onDecoded` `grabCanvas` `grabPixels` `zxDecodeCanvas` `jsqrRead` `jsqrCanvas` `zxHints` `getNativeDetector` `ensureZXing` `ensureJsQR` `decodeImageFile` `ticketHtml` `renderFlightBar` `loadFlights` `persistFlights` `adaptiveBin` `boostContrast` `unsharp` `shBuf` `nextPass` `withTimeout` `frameBrightness` `sharpness` `refocus`
  - ⚠️ 특히 **스캔 순서를 바꾸지 말 것.** 카메라를 먼저 켜고 그다음에 인식기를 고르는 순서인데, 이걸 뒤집으면 아이폰에서 카메라 권한이 조용히 거부된다
  - ⚠️ 인식기에 **화면을 직접 넘기지 말고 캔버스로 떠서 넘길 것**(`grabCanvas` → `zxDecodeCanvas`). 영상을 그대로 넘기면 화면은 나오는데 아무리 비춰도 인식이 안 된다 (실제로 겪은 문제)
  - ⚠️ **`SCAN_PASSES` 9가지를 줄이지 말 것.** 인쇄된 탑승권은 한 가지 방식으로만 보면 자주 놓친다. 실제 종이 탑승권 사진으로 재보면 **촬영 거리마다 이기는 갈래가 매번 다르다.** 세 축을 섞어 쓴다:
    - `adap` — 자리마다 밝기를 따로 재서 검정/흰색을 가른다 (번들거림·굽은 종이·그림자). **화면 전체 밝기를 한꺼번에 늘리는 방식(`boost`)으로는 한쪽만 밝은 사진을 못 잡는다**
    - `max` — 줄이는 크기를 갈래마다 다르게 한다. 같은 사진도 **줄이는 크기에 따라 읽히고 안 읽힌다**
    - `zoom` — 가운데만 확대한다 (코드가 멀리서 작게 잡힐 때)
  - ⚠️ **기기 내장 인식기(BarcodeDetector)만 믿지 말 것.** 같은 폰에서 **두 번 연속으로 사용자를 막은 함정**이다. 안드로이드에서 Play 서비스의 바코드 부품이 없거나 받는 중이면 내장 인식기가 세 가지로 고장 난다: 빈손만 돌려주거나 · 오류를 던지거나 · **아예 답을 안 준다**
    - ⚠️⚠️ **내장 인식기를 부를 때는 반드시 `withTimeout`으로 감쌀 것.** `await det.detect(v)`만 걸어두면 답이 없는 기기에서 **스캔 루프가 첫 프레임에서 멎는다.** `await BarcodeDetector.getSupportedFormats()`가 멎으면 **스캔이 시작조차 못 한다** (카메라 화면만 뜨고 아무 반응 없음). `try/catch`로는 못 잡는다 — 오류가 아니라 그냥 안 끝나는 것이라서
    - 제한 시간을 두 번 넘기면 **내장 인식기를 아예 끄고** 우리 인식기만 쓴다
    - 인식기를 **하나로 합쳐서** 매 프레임 내장 → ZXing/jsQR 을 다 돌릴 것. "내장이 실패하면 그때 갈아탄다"는 구조는 위 세 번째 고장(답이 없음)에서 갈아타는 코드 자체가 실행되지 않아 소용없다
  - ⚠️ 사진에서 찾는 경로(`decodeImageFile`)에서도 **인식기가 없으면 만들어 줄 것.** 카메라를 켤 때만 만들면 사진만 넣었을 때 조용히 실패한다 (실제로 겪은 문제)
  - ⚠️ 저장 구조에 `w`(가보고 싶은 곳)·`r`(예비)가 포함됨. 병합 로직에서 이 두 칸을 빠뜨리면 **두 사람 사이에서 기록이 사라짐**
  - ⚠️ **접이식 메뉴를 여는 연결(`setupFold`)을 `render()` 안에 두지 말 것.** 화면을 다시 그릴 때마다
    클릭이 중복 등록돼 한 번 눌러도 두 번 뒤집혀 그대로다. **시작할 때 한 번만** 걸고
    `head.dataset.fold` 표식으로 두 번 걸리는 것도 막는다 (실제로 겪은 문제)
- 수정 후 반드시 `node --check`로 문법 검증
- **탑승권 인식 쪽을 건드렸으면 검증 도구를 반드시 돌릴 것** (jeju 저장소의 `tools/`):
  ```bash
  pip install qrcode pillow pdf417gen
  python3 tools/make-test-passes.py /tmp/passes   # 시험 이미지 20장 생성
  node tools/verify-scan.mjs /tmp/passes          # 실제 스캔 경로로 확인
  ```
  기준값 **16/20 인식 · 실시간 카메라 흐름 통과 · 내장 인식기 고장 흉내 4가지 통과**
  (빈손 / 오류 / 답이 영영 없음 / 형식 조회부터 답이 없음). 이보다 떨어지면 뭔가 망가진 것이다
  (실패하는 4건은 심하게 흐린 종이 PDF417 — ZXing 의 한계다. 안드로이드 내장 인식기는 이 경우도 대부분 읽는다)
- 새 지역판을 만들 때 `tools/`와 `CLAUDE.md`는 **jeju 저장소 안에 그대로 두면 된다** (사이트에서 쓰지 않는 개발용 파일)

### 5단계. 배포 (같은 저장소, 새 파일)
새 지역은 **기존 jeju 저장소에 `{지역영문}.html`로 추가**한다.
- 배포 주소: `https://goldlucky7.github.io/jeju/busan.html` 형식
- `updates.json`은 지역별로 파일명을 나눈다 (예: `busan-updates.json`) → 해당 html의 `UPD_URL`을 그 파일명으로 수정
- **배포 방법 (순서대로 시도)**:
  1. 세션에 GitHub 연동 도구(mcp/gh 등)가 있고 goldlucky7/jeju 저장소에 접근 가능하면 **토큰 없이 그 도구로 직접 커밋·푸시** (가장 간단)
  2. 안 되면 GitHub Contents API 사용:
```
1) GET https://api.github.com/repos/goldlucky7/jeju/contents/{파일명}  → 기존 파일이면 sha 확보 (신규면 sha 생략)
2) PUT 같은 주소, body: {"message":"...", "content":"<base64>", "sha":"<있을 때만>"}
   헤더: Authorization: Bearer <PAT>
```
- **PAT(토큰)**: 🔒 보안상 토큰은 이 파일에 저장하지 않는다. 이 스킬이 담긴 저장소는 공개(public)라서 토큰을 적어두면 GitHub이 자동으로 무효화한다. Contents API가 필요하면 사용자에게 "예전에 만든 jeju 배포용 토큰을 붙여넣어 주세요"라고 짧게 요청할 것
  - 토큰 사양: fine-grained, jeju 저장소 한정, Contents R/W + Pages R/W (현재 발급본 만료: 2026-09-27)
  - 401/403 에러가 나면(만료·무효화): 사용자에게 새 fine-grained 토큰 발급을 스크린샷 단계별로 안내 (jeju 저장소 한정, Contents+Pages R/W 권한)
  - ⚠️ 받은 토큰을 이 스킬 파일이나 저장소 어디에도 다시 적지 말 것
- 업로드 후 1~2분 내 자동 재배포. 사용자는 아무것도 안 해도 됨

## 해외 지역판을 만들 때 (하노이판에서 얻은 것)

국내판과 달라지는 지점이 정해져 있다. 아래는 하노이판에서 실제로 바꿔야 했던 것들이다.

- **지도 링크(`NM`)를 구글지도로 바꿀 것.** 네이버지도는 해외를 제대로 못 찾는다.
  `n => "https://www.google.com/maps/search/?api=1&query=" + encodeURIComponent(n + " 도시명")`
  - `VJ`는 그 나라 관광포털이 부실하면 **트립어드바이저 검색**으로 대체하면 잘 맞는다
  - `REV`(네이버 "○○ 후기")와 `PHOTO`(네이버 이미지)는 **한국인 후기를 찾는 용도라 그대로 두는 게 낫다.** 앞에 붙는 지역명만 바꾼다
- **주차(`PK`·`PKT`)는 '가는 법'으로 용도를 바꿀 것.** 해외에서 부부가 직접 운전할 일이 없다.
  하노이판은 `walk`(도보권) / `metro`(지하철) / `grab`(그랩 10분) / `far`(그랩 20~40분) / `tour`(당일치기)로 재정의했다.
  `PKT` 라벨과 `makeCard` 안의 `가는 법` 글자, `PKMAP`(구글지도 길찾기)만 고치면 되고 `pkOf`·`byPk` 로직은 그대로 쓴다
- **전화번호(`TEL`)는 비워도 된다.** 현지 가게 번호는 공식 확인이 어렵다. **지어내지 말고 `const TEL={};`로 두면** 전화 버튼만 안 나올 뿐 나머지는 멀쩡하다.
  대신 **대사관·긴급 병원 번호**를 `COUPONS`에 카드 하나로 넣어주면 훨씬 쓸모 있다
- **`COUPONS`는 '할인'만이 아니라 '아끼는 법 + 꼭 알아둘 것'으로 넓게 잡을 것.**
  해외엔 지역화폐가 없는 대신 이런 게 있다 — 무료 개방일 / **부가세(VAT) 환급** / 정찰요금 앱(그랩 등) / 대중교통 일일권 / 긴급 연락처.
  모달 제목도 그에 맞게 바꾼다
- **`GLOSSARY`가 국내판보다 훨씬 중요하다.** 음식 이름(퍼·분짜·반미…)과 주소 표기(포·응오·쭈아…)를 모르면 카드를 못 읽는다. 60개 이상 넣을 것
- **`AIRLINES`는 `cut`(국내선 마감)을 쓰지 않는다.** 전부 국제선이므로 표 문구를 `국제선 출발 N분 전` 하나로 줄이고, `hr`에서 "국내선 …" 부분을 뺀다
- **`apLive()`에 현지 공항 한 줄을 추가**해야 [실시간 운항] 버튼이 산다 (`if(c==="HAN") return "…";`). ICN 처리 바로 아래에 같은 모양으로 붙이면 된다
- **좌표(`LL`)를 지오코딩 도구 없이 채워야 할 때**는 검증한 도로명 주소를 기준으로 잡는다. 구시가지처럼 좁은 구역은 몇십 m 오차가 나도 거리순·동선 기능에 지장이 없다. 대신 **사용자에게 "대략값"이라고 알려줄 것**

### 데이터 블록을 갈아끼울 때 조심할 것 (실제로 겪은 함정)

- ⚠️ **블록의 끝을 `];`·`};`가 열 0에 오는 줄로 찾으면 안 된다.** `ZONE_KW`처럼 **닫는 괄호가 줄 안쪽에 있는 블록**이 있어서, 그렇게 찾으면 범위가 뒤쪽까지 넘어가 `zoneOf`·`renderZoneMenu`·`setupFold` 같은 **로직 함수가 통째로 지워진다.**
  반드시 **여는 괄호와 짝을 세어서** 끝을 찾을 것 (문자열·주석 안의 괄호는 빼고)
- 교체가 끝나면 `node --check`만으로는 부족하다. **브라우저로 실제로 띄워** 아래를 확인할 것
  (컨테이너에 Chromium과 Playwright가 이미 깔려 있다 · `executablePath: '/opt/pw-browsers/chromium'`)
  - `PLACES` 개수 = 헤더 `N PLACES` = `<title>` 숫자
  - 좌표·권역·강도·가는 법·맛집종류·가성비그룹에 **빠진 장소가 0곳**인지
  - `MUST`·티어·`LL` 같은 맵에 **PLACES에 없는 id가 남아 있지 않은지**
  - 칩 16개·권역 10개·강도·티어 그룹의 **곳수가 0이 아닌지**
  - 탭 12개 클릭 / 초성 검색 / 접이식 3개 / 모달 5개(할인·영업시간·장소추가·요즘뜨는곳·항공편) / 도장 찍기
  - `updates.json`은 `file://`로는 CORS 때문에 안 읽힌다. **로컬 http 서버로 띄워서** 확인할 것

## "요즘 뜨는 곳 업데이트해줘" 요청일 때

사용자가 앱에서 [🆕 요즘 뜨는 곳] 버튼을 눌렀는데 목록이 비어 있으면 이 요청을 한다.

1. 웹검색·지도로 **최근 1~3개월 내 뜨는 신상 장소** 조사 (리뷰 급증, 평점 4.5 이상 위주)
2. 기존 PLACES에 **없는 곳만** 추린다
3. 해당 지역 `updates.json`을 아래 스키마로 새로 써서 푸시:
```json
{
 "updated": "2026-08-28",
 "title": "8월 4주차 · 요즘 제주에서 가장 뜨는 곳",
 "note": "지도 리뷰와 최근 평점이 빠르게 오르고 있는 곳 위주로 골랐어요.",
 "items": [
  {"id":"upd260828_haejigae","cat":"cafe","emoji":"🌅","name":"해지개카페",
   "region":"애월","addr":"제주시 애월읍 애월북서길 52",
   "tag":"한 줄 소개","hot":"왜 지금 뜨는지 + 웨이팅/품절 팁",
   "desc":"2~3문장 설명","time":"09:00~19:00"}
 ]
}
```
- `id`는 `upd{YYMMDD}_{영문이름}` 형식으로 기존 id와 절대 겹치지 않게
- `hot`에는 리뷰 수·평점·품절 시간 같은 **구체적 근거**를 넣을 것
- 주소·영업시간은 여기서도 반드시 검증 (미확인은 "방문 전 확인")

## 기존 스탬프북 수정 요청일 때

- 제주: `index.html`, 다른 지역: 해당 `{지역}.html`을 raw에서 받아 수정 후 같은 방식으로 푸시
- 장소 추가 시 **주소·영업시간 검증 필수**, 그리고 아래를 새 id 기준으로 함께 추가:
  - `LL`(좌표) · `EFFORT`(활동 강도) · `PK`(주차) · `TEL`(전화) · `ZONE_OF`(권역) · 맛집이면 `FTYPE` · 마사지면 `SPATIER` · 가성비 카페면 `CHEAPG` · 탈것이면 `RIDEG`
  - `TEL`·`LL`은 **확인된 곳만** 넣는다. 없으면 그 줄을 비워두면 되고 카드에서 전화 줄만 빠진다 (없는 번호를 지어내면 사용자가 엉뚱한 데로 전화한다)
  - 어떤 칩에도 안 걸리면 해당 칩 `keys`에 그 장소의 단어를 추가 (칩 로직 자체는 수정 금지)
  - 같은 테마 장소를 **3곳 이상 한꺼번에 추가했으면 `CHIPS`에 칩을 하나 새로 만들 것**. `cats`에는 그 장소들이 걸쳐 있는 카테고리를 전부 넣고(빙수는 `["cafe","food"]`), `keys`에는 이름·해시·설명에 실제로 들어 있는 말만 넣는다
  - 장소마다 **카드 이모지(emoji)를 서로 다르게** 주면 목록에서 한눈에 구분됨 (같은 테마라고 전부 같은 이모지를 쓰지 말 것)
  - 장소를 더했으면 `<title>` · 헤더 `· N PLACES` · 소개 문장의 **곳수 숫자 3곳을 전부 다시 세서 고칠 것** (자주 빠뜨리는 부분)
- 장소를 더하는 작업은 항공편 기능과 무관하다. 다만 **`lib/` 폴더는 지우지 말 것** (지우면 탑승권 인식이 죽는다)
- TextDB 키·연동 로직은 절대 변경 금지 (바꾸면 기존 도장이 전부 사라짐)

### 카테고리를 통째로 새로 만들 때 (예: 🎢 탈것·놀이기구)

장소 몇 개 추가와 달리 **탭 하나가 새로 생기는 작업**이다. 아래 10곳을 전부 손대야 하고,
하나라도 빠지면 탭은 보이는데 안이 비거나 색이 깨진다. (제주판 `ride` 추가가 이 순서였다)

| # | 고칠 곳 | 무엇을 |
|---|---|---|
| 1 | CSS `.v-{키}` `.b-{키}` | 카드 윗부분 그림 배경색과 배지색. 없으면 **카드 윗칸이 흰색으로 비어 보임** |
| 2 | CSS `.{키}-head` | 탭 맨 위 안내 박스 (가성비 카페 `.cheap-head`와 같은 모양으로) |
| 3 | `<nav id="tabs">` | 장소 종류 탭 줄에 버튼 추가 (`data-filter="{키}"`). ⚠️ **`#myRow`(내 여행)에 넣지 말 것** |
| 4 | `PLACES` | `cat:"{키}"`로 장소 본문 추가 |
| 5 | `CAT` · `CATS` · `CAT_EMOJI` | 이름표·출력 순서·이모지 세 곳 모두. **`CATS`에 안 넣으면 [전체] 목록에 아예 안 나옴** |
| 6 | `TEL` `PK` `EFFORT` `ZONE_OF` `LL` | 새 id 기준으로 채우기 (확인된 것만) |
| 7 | `{키}G` / `{키}_GROUPS` + `add{키}Groups()` | 묶음 정의와 출력 함수. `addCheapGroups`를 그대로 본떠 만들 것 |
| 8 | `render()` 안의 분기 | `else if(cat==="{키}") add{키}Groups(items);` 한 줄. **빠뜨리면 그룹 없이 카드만 쏟아짐** |
| 9 | `CHIPS` | 새 카테고리를 잡는 칩 1~2개. ⚠️ `cats`만 넣고 `keys`를 비우면 **아무것도 안 걸린다** (`chipMatch`는 `keys` 중 하나가 글에 있어야 통과) |
| 10 | 곳수 표기 **네 군데** | `<title>` · 헤더 `· N PLACES` · 머리말 소개문 · 「처음이신가요?」 안내문 |

- 칩을 만든 뒤 **그 카테고리 장소가 전부 걸리는지 세어볼 것.** 제주판에서 조랑말체험공원 한 곳이 빠졌다 (`keys`에 `승마`는 넣었는데 그 카드엔 `조랑말`만 있었음)
- `GLOSSARY`에 그 분야 용어를 함께 넣으면 카드 설명에 점선 밑줄이 자동으로 붙는다 (탈것=짚라인·ATV·버기카·활공장·도항선 등)
- 다 고친 뒤 **브라우저로 실제로 열어 확인**: 탭 클릭 → 그룹 머리글 → 카드 수 → 칩 곳수 → 지역 필터 → 다른 탭 회귀. `node --check`만으로는 8·9번 누락이 안 잡힌다

## 주의사항

- TextDB는 30일간 접속 없으면 데이터 삭제됨 (사이트를 열기만 해도 타이머 리셋) — 오래 안 쓴 지역이면 사용자에게 알려줄 것
- 저장 시 항상 "최신 fetch → 내 변경만 병합 → push" 패턴 유지 (동시 수정 덮어쓰기 방지)
- 장소 설명(desc)은 2~3문장, 실용 팁(웨이팅, 예약, 동선) 포함
- MUST·MUSTEAT 등 추천 이유 문구는 **"왜 여기여야 하는지"를 구체적으로** (다른 데선 못 하는 경험, 가격, 시간대). "좋아요/유명해요" 같은 빈말 금지
