# 여행 스탬프북 제작 스킬

부부(사용자 + 신랑) 2인용 여행 팸플릿 웹사이트를 만드는 스킬. 제주 스탬프북(https://goldlucky7.github.io/jeju/)과 동일한 구조로 새 지역 버전을 만든다.

## 사용자 성향 (반드시 준수)

- **비개발자, 안드로이드 폰으로만 작업.** 기술 용어 최소화, 결과 위주로 소통
- **번거로운 것 싫어함.** 질문은 꼭 필요한 것만 1~2개로 압축 (지역, 장소 개수 정도)
- 신랑은 Claude 계정 없음 → 반드시 GitHub Pages 링크로 배포 (Claude 게시 링크 금지)
- 로그인·코드입력 없는 자동 연동 필수 (TextDB 10초 폴링 방식 유지)
- **팩트체크 중시**: 모든 장소의 주소·영업시간을 지도/웹검색으로 교차 검증. 미확인 정보는 "매장 확인"으로 표기 (지어내기 절대 금지)

## 완성품 스펙 (제주판 = 295곳 기준)

### 카테고리·탭
- 8개 카테고리: 관광지 99 + 맛집 55 + 카페 49 + 소품샵 12 + 술집·안주 15 + 호텔 15 + 마사지 26 + 가성비 카페 24 (카페 49곳 안에 🍧 빙수·팥빙수 8곳 포함)
- 탭: 전체 / ⭐ 꼭 가볼 곳 / 🏝 관광지 / 🍽 맛집 / ☕ 카페 / 🛍 소품샵 / 🍻 술집·안주 / 🏨 호텔 / 💆 마사지 / 💸 가성비 카페 / ⭐ 내 일정 / 🔴 갔다온 곳
- ⚠️ 헤더의 곳수 표기(`... · N PLACES`)는 실제 PLACES 개수와 **반드시 맞출 것**. 장소를 더할 때 `<title>` · 헤더 · 소개 문장 세 군데가 따로 놀기 쉬우니 셋을 한꺼번에 고칠 것 (제주판은 263으로 어긋나 있던 걸 295로 맞춰둠)
- **도장 찍은 곳은 목록에서 사라지고 [🔴 갔다온 곳] 탭에 모임** (`passes()`에서 처리)

### 우선 추천 (카테고리별 "꼭 가야 할 곳")
- ⭐ **꼭 가볼 곳 탭(MUST)**: 필수 코스 모음. 이 탭은 **거리·지역·강도 필터를 자동 해제**하고 섬 전체를 보여줌. 카드에 "왜 꼭 가야 하냐면" 한 줄 이유
- 🔥 **MUSTEAT**(죽어도 맛봐야 할 집) — "이건 제주에서만" 이유 문구
- 소품샵/술집/호텔은 **티어 그룹**으로 묶어 출력 (TIERMAP)
  - 소품샵: 💎 죽어도 가봐야 하는 / 🎀 특이한 / 🛍 그 밖의
  - 술집: 🔥 죽어도 가야 할 / 🍺 맥주 한잔 / 🍢 대표 안주가 확실한
  - 호텔: ✨ 청소·친절 우수 / 🏨 그 밖의 3~5성급 + 성급 배지(STARS)
  - 마사지: 🌿 오일·아로마 테라피 / 👐 중국식·발마사지·지압 / 🇹🇭 타이마사지 (SPA_T·MUSTSPA)
- 💸 **가성비 카페**는 티어 대신 **상황별 3그룹**(CHEAP_GROUPS): 🌊 바다·경치 좋은 지점 / 🚗 이동 중 들르기 좋은 지점 / 🏙 시내·시장 안. 빽다방·메가커피·컴포즈 중 **자리나 위치가 쓸모 있는 지점만** 선별

### 필터·탐색
- 🔍 검색창: 이름·지역·태그·해시·설명·주소 통합, 띄어쓰기 무시, **초성 검색**(예: ㅇㅈㅎㅈㄱ), ✕ 초기화
- 세부 카테고리 칩 17개: **카테고리 + 맛집 종류 + 키워드 3중 판정**(`chipMatch`)
  - 칩은 탭 하나에 묶이지 않아도 됨. `cats`에 카테고리를 여러 개 넣으면 **탭을 가로지르는 테마 칩**이 된다 (예: `🍧 빙수·팥빙수` = `cats:["cafe","food"]`로 카페·맛집을 한꺼번에 잡음)
- 📍 지역별로 보기: 권역 버튼 10개 (이모지·이름·곳수, 재클릭 해제) + 카드에 권역 배지
- 📍 **내 주변 15km 이내 보기**(NEAR_LIMIT_KM): 위치 권한 → 직선거리 가까운 순 상위 30곳, 🧭 거리 배지
- 🧭 **얼마나 움직여야 하나요?(EFF)**: 실내 → 시원한 야외 → 차로 바로 → 야외 → 걷는 곳 → 약간 등산. **덜 힘든 순서로 그룹핑**, 카드에 강도 배지. 더운 날·비 오는 날 대응
- 맛집은 종류별 그룹(FT 8종): 해산물·회 / 해장국·국밥 / 국수 / 흑돼지·고기 / 돈까스 / 수제버거 / 김밥·분식·치킨 / 그 외
- **지금 필터 바**: 켜져 있는 필터를 태그로 보여주고 개별 ✕ 해제 + 현재 곳수 + [전체 해제]
- 위 필터는 전부 동시 적용(AND)

### 카드 정보
- 🅿️ **주차 정보(PK)**: 무료 / 무료·좁음 / 유료 / 인근 공영 / 갓길 배지 + 안내 팁 + [이 근처 주차장 지도로 보기]
- 📋 **주소 복사** 버튼, 📷 **대표 사진 보기**(네이버 이미지 검색), 📞 **전화 걸기**(TEL, 탭하면 바로 통화)
- 카드마다 **바깥 링크 3종**: 🗺 네이버지도(`NM`) · 관광포털 검색(`VJ`) 또는 관련 기사 · 📝 **후기·정보**(`REV` = 네이버에서 "장소명 지역 후기" 검색)
  - ⚠️ 링크 헬퍼는 **반드시 장소 이름을 받아 검색 주소를 만드는 함수**여야 함. 홈페이지 주소만 넣으면 어느 카드를 눌러도 메인으로 가버림
- 맛집·카페·술집: 영업시간/브레이크타임/휴무일 3줄 + 🕐 영업시간표 전체 모달
- 술집은 🍢 대표 안주(anju) 줄 추가

### 도우미 기능
- 🤖 **모르는 말 바로 찾기(GLOSSARY ~78개)**: 카드 설명에서 사전에 있는 말에 **점선 밑줄**이 자동으로 그어지고, 누르면 뜻 팝업. 검색창으로도 찾기 가능
  - 사전에 없는 말은 **아무 글자나 길게 눌러 선택 → [🤖 이 말 뜻 찾기]** 버튼 → AI(Perplexity)·검색·사진 링크로 연결
- 🆕 **요즘 뜨는 곳 업데이트 받기**: 같은 폴더의 `updates.json`을 읽어 새로 뜨는 장소를 카드로 보여주고, 개별 담기 / [전부 내 목록에 담기] 가능. 이미 목록에 있는 곳은 "이미 담김" 처리
- ⭐ **내 일정 탭(plan)**: 카드마다 [☆ 가보고 싶어요]를 누르면 여기에 모임. 곳마다 **방문 예정 날짜** 지정 가능하고, **📍 지역별 / 📅 날짜별** 묶음 보기를 버튼으로 전환. 날짜 정한 곳·다녀온 곳 수를 위에 요약
- 🚗 **동선 순서**: 내 일정의 각 묶음(지역·날짜) 안을 **들르기 좋은 순서로 자동 정렬**. 카드에 순번(①②③)과 **앞 지점에서의 거리**가 붙고, 묶음 머리글에 `🚗 동선 순서 · 총 ○○km` 표시
  - 출발 방향은 **내 위치를 알면 가까운 쪽에서**, 모르면 **공항에서 가까운 쪽에서** 시작
  - 좌표 없는 곳은 순번 없이 맨 뒤로 밀리고 "순서를 못 매긴 곳 N곳"으로 안내
- 🎟 **렌터카 제휴 할인(LOTTE)**: 롯데렌터카 제주 웰컴 쿠폰팩 제휴처 39곳을 표시. 해당 장소 카드에 🎟 배지와 할인율이 붙고, **할인율을 직접 적어두면 두 사람에게 공유**됨(직접 적은 값 우선, 없으면 기사 확인분). 전체 목록은 [🎟 롯데렌터카 할인되는 곳 보기] 모달
- ✈️ **항공편 · 탑승권 QR 인식**: [✈️ 항공사 운영시간 · 탑승권 QR 인식] 버튼 하나에 세 화면이 들어 있음
  - 🎫 **탑승권 인식** — 카메라로 비추거나(📷) 사진에서 찾거나(🖼) 직접 입력(⌨️). 탑승권 바코드에서 편명·출발/도착 공항·날짜·좌석·예약번호·이름을 읽음
    - ⚠️ **탑승권 바코드에는 출발 시각과 탑승구가 없다**(국제 규격 자체에 그 칸이 없음). 출발 시각만 한 번 넣으면 **공항 도착 권장 / 수속·수하물 마감 / 탑승 시작 / 탑승구 마감 / 남은 시간**을 계산해줌
    - 저장하면 메인 화면 위쪽에 **다음 항공편 카운트다운 바**가 뜨고, 누르면 바로 그 화면으로 감
    - 🔒 탑승객 이름·예약번호가 들어가므로 **두 사람 공유 저장소에 올리지 않고 각자 기기에만 저장**(`jeju_flights_v1`). 이 원칙을 깨고 공유 저장소로 옮기지 말 것
  - 🕐 **항공사 운영시간** — 그 지역 노선 항공사의 고객센터 번호·상담시간·수속 마감 기준을 카드로. 공항 콜센터도 함께
  - 🧭 **공항에서 어디로** — 공항 층별 구조와 탑승까지 단계 안내. 탑승구는 당일 배정이라 **실시간 운항정보 링크**로 연결
- ➕ 장소 추가/삭제(카테고리·강도·메모 선택), 백업/복원, 두 사람 도장·추가 장소·가보고 싶은 곳·할인율 자동 연동(로그인 없음)
  - 저장 구조: `{v:도장, c:추가한 장소, w:가보고 싶은 곳+날짜, r:할인율 메모}`

## 제작 순서

### 1단계. 요구 확인 (질문 최소화)
지역이 명확하면 개수·컨셉만 짧게 확인하고 바로 시작. 기본값: 관광지 60 + 맛집 30 + 카페 25 + 소품샵 10 + 술집 12 + 호텔 12 + 마사지 15 + 가성비 카페 15 (지역 규모에 맞게 조정).

### 2단계. 템플릿 다운로드 (처음부터 코딩 금지)
```
GET https://raw.githubusercontent.com/goldlucky7/jeju/main/index.html
GET https://raw.githubusercontent.com/goldlucky7/jeju/main/updates.json
```
bash에서 curl로 받는다. 이 파일이 검증된 완성 코드이므로 **데이터만 교체**하고 로직은 절대 건드리지 않는다.

### 3단계. 장소 조사 + 검증 (가장 중요)
- 웹검색으로 해당 지역 인기 장소 후보 선정 (최신 트렌드 반영, 20~40대 취향)
- 지도 검색 도구(places_search)로 **전 장소 검증** (10개씩 묶어 조회). 장소마다 아래를 함께 수집:
  - 주소 · 영업시간/브레이크타임/휴무일 (미확인은 "매장 확인")
  - **위도·경도** (내 주변 기능용 LL)
  - **전화번호** (TEL) — 확인된 곳만
  - **주차 상황** (무료/무료좁음/유료/공영/갓길 중 하나)
  - **활동 강도** (실내/시원한 야외/차로 바로/야외/걷는 곳/약간 등산)
  - 맛집이면 **음식 종류** (해산물/해장국/국수/고기/돈까스/버거/분식/그 외)
- 호텔은 성급, 술집은 대표 안주, **마사지샵은 시술 계열**(오일·아로마 / 중국식·발 / 타이)도 함께 조사
- **가성비 카페**는 저가 프랜차이즈(빽다방·메가커피·컴포즈 등) 지점 중 **오션뷰·드라이브 동선·시내 접근성** 같은 이유가 있는 곳만 고르고, 그 이유를 그룹(바다·경치 / 이동 중 / 시내·시장)으로 분류
- **한 테마로 3곳 이상 모이면 칩 후보**다. 그 지역의 대표 간식·디저트를 따로 묶어 조사할 것 (제주=팥빙수, 부산=씨앗호떡·밀면, 전주=콩나물국밥 등). 조사할 때 그 테마가 **카페·맛집 중 어느 탭에 흩어져 있는지**도 같이 적어두면 칩 `cats`를 바로 채울 수 있다
- **렌터카 제휴 할인**: 그 지역 렌터카사의 제휴 쿠폰팩 페이지를 찾아 제휴처 목록·할인율을 수집 (확인 안 되면 할인율은 비워두기)
- **관문(공항·역) 정보**: 항공편 기능에 쓸 자료를 같이 조사한다
  - 그 지역에 취항하는 **항공사 목록 + 고객센터 번호 + 상담 운영시간 + 수속 마감 기준**
  - 공항 **여객터미널 층별 구조**(몇 층이 출발/도착/탑승장인지)와 탑승까지의 단계
  - 공항 **실시간 운항정보 페이지 주소**와 공항 코드(예: 제주=CJU)
  - ⚠️ 카운터 번호·탑승구 번호는 **날마다 바뀌므로 적지 말 것.** "전광판에서 확인"으로 안내하고 실시간 조회 링크를 건다 (틀린 번호를 적으면 공항에서 헤맨다)
  - 내륙 지역이라 공항이 없으면 KTX역 등 **관문 기준으로 바꾸거나 이 기능을 통째로 빼면 된다**
- PLACES 항목 구조: `{id, cat(spot|food|cafe|shop|bar|hotel|spa|cheap), emoji, region, name, tag, hash, desc, addr, time(관광지용) 또는 open/brk/closed(가게용), anju(술집), links:[["네이버지도",NM("이름")],[관련 링크]]}`
- id는 영문 소문자, 기존 항목과 중복 금지
- **장소 이름(name)은 지도에서 실제로 검색되는 형태로** 적을 것 (링크·사진·후기 검색이 전부 이름 기반이라 안 맞으면 엉뚱한 결과가 뜸)
  - 프랜차이즈 지점은 공식 지점명보다 **위치를 붙인 이름**이 잘 잡힘 (예: `빽다방 제주도두점` → `빽다방 (도두 서해안로)`)
  - 시장·상가 안의 가게는 도로명보다 **지번 + "○○시장 내"** 표기가 정확 (예: `서귀포시 서귀동 275-29 (서귀포매일올레시장 내)`)
  - 브랜드명 자체가 맞는지도 확인 (지점 이름만 보고 브랜드를 잘못 적는 실수가 잦음)

### 4단계. 코드 수정 — 교체할 데이터만
아래 목록을 **새 지역 데이터로 전부 교체**한다. 하나라도 빠지면 해당 기능이 조용히 죽으므로 반드시 확인:

| 데이터 | 내용 | 누락 시 증상 |
|---|---|---|
| `PLACES` | 장소 본문 전체 | — |
| `CHIPS` | 세부 카테고리 칩 (cats/ft/keys). `cats`에 카테고리를 여러 개 넣으면 탭을 가로지르는 테마 칩이 됨 | 칩 눌러도 0곳 |
| `ZONES`/`ZONE_OF`/`ZONE_KW` | 권역 목록·id 매핑·주소 키워드 | 권역 배지 없음 |
| `LL` | 장소 좌표 `id:[위도,경도]` | 내 주변 목록에서 빠지고 **동선 순번도 안 매겨짐** |
| `JEJU_AIRPORT` | 동선 출발 기준점 `[위도,경도]` | 동선 방향이 엉뚱하게 잡힘 |
| `EFFORT` | id별 활동 강도 | "미분류"로 빠짐 |
| `PK` | id별 주차 유형 | 주차 배지·팁 없음 |
| `TEL` | id별 전화번호 | 전화 버튼 없음 |
| `FTYPE` | 맛집 id별 음식 종류 | 맛집 종류 그룹 어긋남 |
| `MUST` | 필수 코스 + 이유 문구 | ⭐ 탭이 빔 |
| `MUSTEAT` | 죽어도 맛봐야 할 집 + 이유 | 맛집 강조 사라짐 |
| `MUSTSHOP`/`SHOPTIER`, `MUSTBAR`/`BARTIER`, `MUSTHOTEL`/`HOTELTIER`, `STARS`, `MUSTSPA`/`SPATIER` | 소품샵·술집·호텔·마사지 추천/티어/성급 | 티어 그룹 어긋남 |
| `CHEAPG`/`CHEAP_GROUPS` | 가성비 카페 id별 그룹(바다/이동/시내) | 가성비 탭이 그룹 없이 쏟아짐 |
| `LOTTE_ALL`/`LOTTE_URL` | 렌터카 제휴처 목록·할인율·쿠폰팩 주소 | 🎟 배지·할인 모달 사라짐 |
| `GLOSSARY` | 그 지역 용어 사전 | 점선 밑줄 사라짐 |
| `AIRLINES` | 그 지역 노선 항공사 + 고객센터 번호·상담시간·수속 마감(분) | 운영시간 화면이 엉뚱한 항공사로 채워짐 |
| `AIRPORTS` | 공항 코드→한글 이름 + 실시간 운항정보 경로(`kac`) | 편명을 읽어도 공항이 코드로만 나오고 실시간 링크가 죽음 |
| `CJU_LIVE` | 그 지역 공항 실시간 출발·도착 페이지 주소 | [실시간 운항·탑승구] 버튼이 제주로 감 |
| `AP_STEPS` | 공항 층별 구조·탑승까지 단계 안내 | "공항에서 어디로" 화면이 제주공항 설명 그대로 남음 |
| `VJ`(관광포털 검색) / `REV`(후기 검색) | 카드 바깥 링크를 만드는 함수 | 링크가 엉뚱한 곳으로 가거나 후기 버튼이 사라짐 |

- 제목/헤더 문구를 새 지역으로 (예: "부산 여행 스탬프북"). **헤더의 `· N PLACES` 숫자는 실제 PLACES 개수를 세어서 정확히 넣을 것**
- 칩·권역·강도는 **실제 PLACES 데이터에 등장하는 단어**로 구성. 완성 후 버튼마다 곳수 0이 아닌지 확인
- **동선 출발 기준점(`JEJU_AIRPORT`)을 새 지역의 관문으로 교체** (그 지역 공항·KTX역 등 여행 시작점 좌표). 변수명은 그대로 두고 값만 바꿔도 됨
- 검색창 placeholder 초성 예시도 새 지역 대표 장소로 교체
- **`VJ`는 그 지역 관광포털 검색 주소로 교체** (제주=비짓제주). 해당 포털이 없으면 대표 관광 사이트나 관련 기사 링크로 대체. `REV`(네이버 후기 검색)는 지역과 무관하므로 그대로 사용
- GLOSSARY는 그 지역 방언·향토음식·지형 용어로 재구성 (제주판 오름·곶자왈·몸국 등은 제주 전용)
- 테마색은 지역 특색으로 변경 가능 (제주=청록+감귤). 예: 부산=바다남색+갈매기, 전주=한옥 갈색+먹색
- **TextDB 커플 키는 반드시 새로 생성**: `{지역영문}stamp_` + 랜덤 32자리 hex (예: `busanstamp_a1b2...`)
  - ⚠️ 제주 키(`jejustamp_3c5491d5379e4abce2a377bae7987b6c`)를 재사용하면 데이터가 섞이므로 절대 금지
- `updates.json`도 새 지역용으로 같은 폴더에 함께 배포 (아래 스키마 참고)
- **인식기 파일 `lib/` 를 반드시 같이 둘 것**: 탑승권을 읽는 프로그램(`lib/zxing.min.js`, `lib/jsQR.js`)이 저장소에 들어 있고 페이지가 이 경로를 먼저 읽는다.
  - 새 지역도 **같은 jeju 저장소 안에** 만들면 `lib/`를 공유하므로 손댈 것이 없다
  - 다른 저장소로 옮길 땐 `lib/` 폴더를 **통째로 같이 복사**할 것. 빠뜨리면 외부 주소로 받으러 가는데, 막힌 통신망이나 광고 차단기 뒤에서는 인식이 통째로 죽는다
- **로직은 전부 변경 금지**: `toCho` `matchesSearch` `chipMatch` `zoneOf` `effOf` `pkOf` `ftOf` `passes` `render` `makeCard` `distKm` `fmtDist` `glossify` `openUpd` `drawUpd` `copyAddr` `setAiLinks` `renderPlan` `renderPlanByZone` `renderPlanByDate` `toggleWish` `setWishDate` `saveWish` `saveRate` `rateOf` `rateSrc` `addCheapGroups` `addTierGroups` `drawLotte` `fmtDay` `daysAway` `routeOrder` `addRouteGrid` `routeNote` `hopKm` `pathLen` `llOf`, fetch→병합→push 패턴, 10초 폴링, visibilitychange
  - 항공편 쪽도 전부 변경 금지: `parseBCBP` `bcbpShift` `parseLoose` `parsePass` `julianToISO` `flightTimes` `pickEngine` `startScan` `stopScan` `onDecoded` `grabCanvas` `grabPixels` `zxDecodeCanvas` `jsqrRead` `zxHints` `getNativeDetector` `ensureZXing` `ensureJsQR` `decodeImageFile` `ticketHtml` `renderFlightBar` `loadFlights` `persistFlights`
  - ⚠️ 특히 **스캔 순서를 바꾸지 말 것.** 카메라를 먼저 켜고 그다음에 인식기를 고르는 순서인데, 이걸 뒤집으면 아이폰에서 카메라 권한이 조용히 거부된다
  - ⚠️ 인식기에 **화면을 직접 넘기지 말고 캔버스로 떠서 넘길 것**(`grabCanvas` → `zxDecodeCanvas`). 영상을 그대로 넘기면 화면은 나오는데 아무리 비춰도 인식이 안 된다 (실제로 겪은 문제)
  - ⚠️ 저장 구조에 `w`(가보고 싶은 곳)·`r`(할인율)이 포함됨. 병합 로직에서 이 두 칸을 빠뜨리면 **일정과 할인율 메모가 두 사람 사이에서 사라짐**
- 수정 후 반드시 `node --check`로 문법 검증

### 5단계. 배포 (같은 저장소, 새 파일)
새 지역은 **기존 jeju 저장소에 `{지역영문}.html`로 추가**한다.
- 배포 주소: `https://goldlucky7.github.io/jeju/busan.html` 형식
- `updates.json`은 지역별로 파일명을 나눈다 (예: `busan-updates.json`) → 해당 html의 `UPD_URL`을 그 파일명으로 수정
- **배포 방법 (순서대로 시도)**:
  1. 세션에 GitHub 연동 도구(mcp/gh 등)가 있고 goldlucky7/jeju 저장소에 접근 가능하면 **토큰 없이 그 도구로 직접 커밋·푸시** (가장 간단)
  2. 안 되면 GitHub Contents API 사용:
```
1) GET https://api.github.com/repos/goldlucky7/jeju/contents/{파일명}  → 기존 파일이면 sha 확보 (신규면 sha 생략)
2) PUT 같은 주소, body: {"message":"...", "content":"<base64>", "sha":"<있을 때만>"}
   헤더: Authorization: Bearer <PAT>
```
- **PAT(토큰)**: 🔒 보안상 토큰은 이 파일에 저장하지 않는다. 이 스킬이 담긴 저장소는 공개(public)라서 토큰을 적어두면 GitHub이 자동으로 무효화한다. Contents API가 필요하면 사용자에게 "예전에 만든 jeju 배포용 토큰을 붙여넣어 주세요"라고 짧게 요청할 것
  - 토큰 사양: fine-grained, jeju 저장소 한정, Contents R/W + Pages R/W (현재 발급본 만료: 2026-09-27)
  - 401/403 에러가 나면(만료·무효화): 사용자에게 새 fine-grained 토큰 발급을 스크린샷 단계별로 안내 (jeju 저장소 한정, Contents+Pages R/W 권한)
  - ⚠️ 받은 토큰을 이 스킬 파일이나 저장소 어디에도 다시 적지 말 것
- 업로드 후 1~2분 내 자동 재배포. 사용자는 아무것도 안 해도 됨

## "요즘 뜨는 곳 업데이트해줘" 요청일 때

사용자가 앱에서 [🆕 요즘 뜨는 곳] 버튼을 눌렀는데 목록이 비어 있으면 이 요청을 한다.

1. 웹검색·지도로 **최근 1~3개월 내 뜨는 신상 장소** 조사 (리뷰 급증, 평점 4.5 이상 위주)
2. 기존 PLACES에 **없는 곳만** 추린다
3. 해당 지역 `updates.json`을 아래 스키마로 새로 써서 푸시:
```json
{
 "updated": "2026-08-28",
 "title": "8월 4주차 · 요즘 제주에서 가장 뜨는 곳",
 "note": "지도 리뷰와 최근 평점이 빠르게 오르고 있는 곳 위주로 골랐어요.",
 "items": [
  {"id":"upd260828_haejigae","cat":"cafe","emoji":"🌅","name":"해지개카페",
   "region":"애월","addr":"제주시 애월읍 애월북서길 52",
   "tag":"한 줄 소개","hot":"왜 지금 뜨는지 + 웨이팅/품절 팁",
   "desc":"2~3문장 설명","time":"09:00~19:00"}
 ]
}
```
- `id`는 `upd{YYMMDD}_{영문이름}` 형식으로 기존 id와 절대 겹치지 않게
- `hot`에는 리뷰 수·평점·품절 시간 같은 **구체적 근거**를 넣을 것
- 주소·영업시간은 여기서도 반드시 검증 (미확인은 "방문 전 확인")

## 기존 스탬프북 수정 요청일 때

- 제주: `index.html`, 다른 지역: 해당 `{지역}.html`을 raw에서 받아 수정 후 같은 방식으로 푸시
- 장소 추가 시 **주소·영업시간 검증 필수**, 그리고 아래를 새 id 기준으로 함께 추가:
  - `LL`(좌표) · `EFFORT`(활동 강도) · `PK`(주차) · `TEL`(전화) · `ZONE_OF`(권역) · 맛집이면 `FTYPE` · 마사지면 `SPATIER` · 가성비 카페면 `CHEAPG` · 렌터카 제휴처면 `LOTTE_ALL`
  - 어떤 칩에도 안 걸리면 해당 칩 `keys`에 그 장소의 단어를 추가 (칩 로직 자체는 수정 금지)
  - 같은 테마 장소를 **3곳 이상 한꺼번에 추가했으면 `CHIPS`에 칩을 하나 새로 만들 것**. `cats`에는 그 장소들이 걸쳐 있는 카테고리를 전부 넣고(빙수는 `["cafe","food"]`), `keys`에는 이름·해시·설명에 실제로 들어 있는 말만 넣는다
  - 장소마다 **카드 이모지(emoji)를 서로 다르게** 주면 목록에서 한눈에 구분됨 (같은 테마라고 전부 같은 이모지를 쓰지 말 것)
  - 장소를 더했으면 `<title>` · 헤더 `· N PLACES` · 소개 문장의 **곳수 숫자 3곳을 전부 다시 세서 고칠 것** (자주 빠뜨리는 부분)
- 장소를 더하는 작업은 항공편 기능과 무관하다. 다만 **`lib/` 폴더는 지우지 말 것** (지우면 탑승권 인식이 죽는다)
- TextDB 키·연동 로직은 절대 변경 금지 (바꾸면 기존 도장이 전부 사라짐)

## 주의사항

- TextDB는 30일간 접속 없으면 데이터 삭제됨 (사이트를 열기만 해도 타이머 리셋) — 오래 안 쓴 지역이면 사용자에게 알려줄 것
- 저장 시 항상 "최신 fetch → 내 변경만 병합 → push" 패턴 유지 (동시 수정 덮어쓰기 방지)
- 장소 설명(desc)은 2~3문장, 실용 팁(웨이팅, 예약, 동선) 포함
- MUST·MUSTEAT 등 추천 이유 문구는 **"왜 여기여야 하는지"를 구체적으로** (다른 데선 못 하는 경험, 가격, 시간대). "좋아요/유명해요" 같은 빈말 금지
